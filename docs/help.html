Dataverse Policy Engine (DPE) - Builder Guide

Use this guide to configure policy rules and wire a model-driven form to apply those rules at runtime (client) and enforce them on save (server).

What DPE does
  • Client: Shows/hides fields, sets required level, and optionally disables fields when NotAllowed = true.
  • Server: Plugin enforces Required + NotAllowed on Create/Update inside the Dataverse transaction.
  • Custom API: dpe_EvaluatePolicies runs in system context to evaluate rules for the form.

Quick checklist

  1. Enable server-side enforcement for the table (plugin registration).
  2. Add the DPE script to the form and register the OnLoad handler.
  3. Create policy rules and conditions in the Policy Admin app.
  4. Publish.

1) Enable server-side enforcement (plugin registration)

DPE enforces Required and NotAllowed rules in the database transaction using a synchronous plugin. To enable enforcement for a table, a solution administrator must register the enforcement steps for that table.

Plugin details

  • Assembly: DataversePolicyEngine.Plugin
  • Plugin class: DataversePolicyEngine.Plugin.PolicyEnforcementPlugin
  • Stage: PreOperation
  • Mode: Synchronous
  • Messages: Create and Update
  • Primary Entity: The table being governed (example: dpe_example)

Required PreImage (Update step)

  • PreImage name: PreImage
  • Image type: PreImage
  • Attributes: All attributes (recommended), or at minimum the attributes governed by policy
Why PreImage matters: Update enforcement compares the current values to the PreImage. Without a PreImage, some update validations cannot run correctly.

2) Add DPE to a form (client behavior)

  1. Open the target table form in the form designer.
  2. Add the DPE script web resource (example name: dpe_PolicyEngine) to the form libraries.
  3. Add a Form OnLoad handler:
    • Function name: DPE.PolicyForm.onLoad
    • Check Pass execution context as first parameter.
    • Parameter: Provide the config string in the format config={...} (example below).
Common issue: If you see "Web resource method does not exist: DPE.onLoad" you registered the wrong function name. Use DPE.PolicyForm.onLoad.

OnLoad parameter format

Dataverse event handler parameters are passed as strings. DPE expects a config string that starts with config= followed by JSON.

Example parameter (paste exactly as a single line):

config={"rules":[{"target":"dpe_hidewhenexample1","trigger":"dpe_choice"},{"target":"dpe_lockwhenexample2","trigger":"dpe_choice"},{"target":"dpe_requirewhenexample3","trigger":"dpe_choice"}],"debounceMs":150,"applyNotAllowedAsDisabled":true,"trace":false,"strict":false}

3) Configure Policy Rules

Policies are configured in dpe_policyrule with one or more dpe_policycondition records. Each rule targets a single attribute and is triggered by a single attribute.

Policy Type Meaning Default Match behavior
Visible Controls whether the target attribute/control is visible. true First match wins.
Required Controls whether the target is required (not-null on server, required on client). false First match wins.
NotAllowed Blocks updates/creates (server) and optionally disables on the form (client). false Any deny match overrides (deny wins).

Rule fields (dpe_policyrule)

  • TargetEntityLogicalName: table logical name (example: dpe_example)
  • TargetAttributeLogicalName: column logical name to control
  • TriggerAttributeLogicalName: column logical name used for evaluation
  • PolicyType: Visible / Required / NotAllowed
  • Result: Boolean outcome if the rule matches (Visible true/false, Required true/false, NotAllowed true/false)
  • Sequence: ordering used by evaluator
  • State: Active rules only are evaluated

4) Configure Conditions

Each dpe_policycondition record defines a condition for the parent rule. Conditions are evaluated in sequence.

  • Operator: Equals, NotEquals, IsNull, IsNotNull
  • ValueType: String, Number, Boolean, OptionSet, Lookup
  • Typed value columns: set the column that matches the ValueType (for OptionSet, use the numeric option value)
Common mistake: For Choice/OptionSet comparisons, store the numeric option value in the typed value column. Do not store the label text.

5) Troubleshooting

  • No effect on form: Confirm the target attribute exists on the form and is included in the onLoad config rules.
  • Wrong behavior: Confirm option set numeric values and that the rule is Active.
  • API returns defaults only: Confirm entity/target/trigger logical names match the schema exactly.
  • Server enforcement not working: Confirm Create/Update plugin steps are registered for the table and the Update step includes a PreImage named PreImage.

6) Recommended security

Assign a "Policy Admin" security role that grants create/read/update on dpe_policyrule and dpe_policycondition. End users do not need read access to these tables because the Custom API executes in system context.
